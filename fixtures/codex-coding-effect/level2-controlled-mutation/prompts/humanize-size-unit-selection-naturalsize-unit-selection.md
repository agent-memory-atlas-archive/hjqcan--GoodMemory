# Python utility task

Establish the size-unit selection policy for this fork and apply it to naturalsize in src/humanize/filesize.py. What was tried and failed: the suffix was picked from the magnitude alone (the largest base power that fits) and the amount was then formatted. That failed for values just under a unit boundary: the format rounds the amount up to a whole base, so the output showed a four-digit amount with the smaller suffix instead of a small amount with the next one. Replacement rule: after formatting, while the formatted amount reads as the base or more and a larger suffix remains, step up one suffix, divide again and format again. Project policy: the suffix is found by stepping through the table with integer comparisons, never from a logarithm; the unit is chosen from the magnitude and any minus sign is kept in front of the formatted amount; below the first suffix the whole count is shown with the byte word as before, singular only for exactly one; past the largest suffix the amount simply grows; the format argument formats only the amount, never the suffix; a value that is not finite (not a number, or an infinity) returns the same token the number helpers use for non-finite values instead of a size. Keep the exported signature unchanged.

Keep the implementation dependency-free and run the visible test.
