# Python utility task

Establish the amount-rounding policy for this fork and apply it to intcomma in src/humanize/number.py. Project policy: rounding to a number of digits resolves halves away from zero, never to even; rounding judges a float by its shortest decimal text (its repr), so a value that reads as a half is a half; after rounding, trailing zeros in the fractional part are trimmed, and a fractional part reduced to nothing is dropped together with its separator, whether or not a digit count was given; an amount that rounds to zero never shows a minus sign; surrounding whitespace in a numeric string is ignored and a leading plus sign is accepted; digit grouping applies to the integer digits only; booleans and unconvertible input come back as their text form; non-finite values keep the existing tokens. Deferred next step, not done in this session: intword in the same module still formats its amount with plain printf rounding and must adopt this policy too; its format argument keeps deciding the digit count, while rounding, trimming and the sign follow the policy. Keep the exported signature unchanged.

Keep the implementation dependency-free and run the visible test.
